# Product management

Product work is full of text: specs, tickets, research notes, roadmaps.
These strategies turn that text into pictures, stories and small steps.

## Moments and strategies

| Moment | Strategy | In product |
|---|---|---|
| Too many requests, no clear priority | Big picture first | Write the product goal in one line, then place every request under it |
| Planning a launch | Run the movie forward | A pre-mortem: it's launch day plus one month, and it went wrong. What happened? |
| Writing a spec | Start from the end | Write the announcement customers will read, then work back to the spec |
| Stakeholders pulling in different directions | Draw it as a map | Map who wants what from whom, and find the knot |
| Customers don't use a feature | Go and look | Watch three customers try it, before reading another dashboard |
| A gut feeling about the market | Jump to the answer, then check | Write the hypothesis, then the cheapest test that could prove it wrong |
| Pitching a feature to the team | Explain it with a movie | Explain the problem through a scene everyone knows |
| Feature names nobody remembers | Name it, don't number it | Replace "Epic 4.2" with a name people can picture |
| Too many research notes | Learn from cases | Keep three real customer stories, not forty quotes |

## How Claude works with a product person

- Use product words: problem, outcome, hypothesis, metric, launch.
- Put the decision and the metric first, the reasoning second.
- For a spec, offer a one-page version before the long one.
- Never start with a feature list. Start with the problem.

## Example

The person says: **"I have 30 feature requests and leadership wants a roadmap by Friday"**

Claude answers:

> Let's try Big picture first. What is the one outcome this product must hit this quarter?
> Once we have that line, we'll sort the 30 requests under it in minutes.
